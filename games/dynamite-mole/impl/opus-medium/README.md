# Dynamite Mole — opus-medium 実装

ボンバーマン系グリッドアクション。素の JavaScript + Canvas 2D + Web Audio。依存パッケージ・ビルドなし。

## 起動方法

```
cd games/dynamite-mole/impl/opus-medium
python3 -m http.server 5106
# ブラウザで http://localhost:5106/dist/index.html を開く
```

URL パラメータ: `?seed=<整数>` `?stage=<1..5>` `?debug=1` `?mute=1` `?touch=1`(仕様 2.5 節どおり)。

## ファイル構成

```
dist/
  index.html      エントリ。canvas 1 枚 + DOM のタッチ UI。<script src="./js/..."> で順に読む
  favicon.svg     自作 16x16 ドット絵の favicon(ヘルメットのモグラ + ダイナマイト)
  js/core.js      定数、ステージ表、mulberry32、決定的ステージ生成(3.3 節)
  js/font.js      自作 5x7 ビットマップフォント(8x8 セル)と描画関数。描画文字列を texts に記録
  js/art.js       全ドット絵をコードで生成(16x16 ドット格子 → 2 倍して 32x32 px)
  js/audio.js     Web Audio の効果音合成、ジングル、BGM ステップシーケンサ
  js/game.js      状態遷移、ルール、固定ステップ更新、入力、snapshot / debug API
  js/render.js    フィールド・HUD・各画面・照明・パーティクルの描画
  js/main.js      起動、requestAnimationFrame ループ(1/60 固定ステップ)、キー/ポインタ入力、レイアウト、タッチ UI
```

## 仕様の解釈と判断したこと

- **ドットの大きさ**: 全アセットを 1 ドット = 2 px に統一。フォントは 2x(HUD・本文)と 3x(見出し)で描いている。3x 見出しは 3 px ドットになるが、仕様 A18 が 1x〜3x を許可しているのでこれに従った(文字はドット絵アセットとは別扱いと解釈)。
- **HUD の行数**: 5.4 節の図は 2 行だが「配置は自由」とあるので、2x フォントで収めるために 3 行にした(SCORE/HI/TIME、STAGE/ライフ/SND、BOMB/FIRE/SPD)。
- **ライフ表示の `x`**: 文字は大文字化して描く規定なので `X3` と描画・記録している。
- **タイトルのロゴ**: ロゴは画像アセットだが、`texts` にも `DYNAMITE MOLE` を記録している(M5 を texts で確認できるように)。
- **点滅する文字**: `PRESS ENTER TO START` は消さずに明暗で点滅させる(どのフレームでも texts に残る)。
- **stageClear 中の表示**: `TIME BONUS +<値>` はカウントアップさせずに確定値で出す(texts の検証と矛盾しないように)。演出(S13)は喜びポーズと出口が開く瞬間のフラッシュの 2 つ。
- **入力バッファ**: 方向キーの keydown(リピートを除く)をバッファに入れ、停止中なら次の tick で 1 歩、移動中ならステップ終了時に使う。
- **爆弾の設置タイミング**: キー押下はフラグにして、3.13 節の順序どおり次の tick の手順 2 で処理する。
- **炎の snapshot**: 同じタイルに複数の炎があるときは 1 件にまとめ、残り時間の長いほうを返す。
- **`killAllEnemies`**: 敵を通常の死亡処理で倒し、`playing`/`paused` 中なら同じ呼び出しの中で出口も開く(次の tick を待たない)。
- **`teleport`**: 岩を壊すときはスコアを加算しない(`clearBlocks` と同じ扱い)。中のアイテム・出口は出現する。
- **`spawnItem` / `spawnEnemy`**: 「空きマス」= WALL でも SOFT でもないマス。
- **`godMode`**: タイムアップ時も死なず、残り時間は 0 のままになる。
- **ハイスコア**: run の終了時(gameOver / gameClear / R による放棄)に 1 回だけ保存。R による放棄では結果画面を出さないので `NEW RECORD!` は表示しない。
- **タブ非表示**: `playing` 中なら自動で `paused` にし、押しっぱなしのキーを解除する。
- **タッチ UI**: `?touch=1` か `(pointer: coarse)` のときは常に表示する(タイトル・結果画面でも表示したまま)。
- **検証時のポート**: 指定の 5106 は、検証中に別のゲームの別の実装担当(同じ opus-medium 枠)の `http.server` が使っていた。そのプロセスには触らず、ルート配信を 5116、深いサブパス確認を 5117 で行った。README の起動手順は仕様どおり 5106 のまま。

## 既知の問題

- 音は合成・スケジューリングのエラーがないことだけを確認した。ヘッドレス環境なので、音色・音量を耳では確認していない。
- `prefers-reduced-motion` の分岐は、エミュレーションでは確認していない。
- 右→下のように 2 キーをほぼ同時に押しても、1 フレームずれて右のステップが先に始まると、その 1 歩(約 0.22 秒)を終えてから下へ曲がる(仕様 3.4 の「ステップ途中で方向転換しない」に従った結果)。
