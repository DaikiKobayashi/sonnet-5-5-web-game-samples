# SUNSET RUSH 仕様書

- game-id: `sunset-rush`
- 表示名: SUNSET RUSH
- この仕様書だけを読んで実装する。質問はできない。数値・手順・名前は本書のとおりに実装し、書かれていない部分だけを実装担当が決める。

---

## 1. 概要

- **一行説明**: 夕焼けを追いかけて海岸線から夜の街まで駆け抜ける、制限時間つきの疑似 3D アーケードレーシング(OutRun 系)。
- **ジャンル**: 疑似 3D(セグメント投影+スプライト拡縮)レース。3 ステージ固定コース。交通車をかわし、チェックポイントで時間を延ばしてゴールを目指す。
- **狙い**: 連続的なスピード感と、1 本の道路を走り抜ける操作感。疑似 3D の描画(カーブ・起伏・スプライト拡縮・視差背景)、ステージごとの絵作り、エンジン音と BGM の作り込みで出来栄えの差が出る。
- **想定プレイ時間**: 1 ステージ約 45〜70 秒、通しで約 3〜4 分(ゲームオーバーなら 1 分未満から)。
- **操作の要点**: 左右でハンドル、↑ でアクセル、↓ でブレーキ。カーブで外へ膨らむ力(遠心力)に逆らって走る。
- **勝敗**: 各ステージの残り時間が 0 になる前にゴールすればステージクリア。3 ステージすべてクリアでエンディング(ランク表示)。時間切れでゲームオーバー。

## 2. 技術スタック

| 項目 | 決定 |
| --- | --- |
| 言語 | JavaScript(ES2020 以降)。TypeScript 不可 |
| 描画 | Canvas 2D(WebGL・DOM 描画は使わない。アセットギャラリー画面のみ DOM 可) |
| 音 | Web Audio API(すべて合成。音声ファイルを使う場合も自作に限る) |
| ライブラリ | **なし**(npm 依存ゼロ) |

環境調査の結果(参考): Node.js v22 / npm 10 / Python 3.11 が使え、npm レジストリにも届くが、本ゲームは依存ゼロなので使わない。

## 3. ゲームルール

### 3.1 状態遷移(scene)

```
title ──Enter──> countdown ──3s──> playing ──ゴール──> stageclear ──Enter──> countdown(次ステージ)
  ^                                   │  │                    └(ステージ3のとき)Enter──> ending ──Enter──> title
  │                                   │  └─時間0──> timeup ──2.5s──> gameover ──Enter/R──> countdown(ステージ1から)
  │                                   │                                   └─Esc/Q──> title
  │                                   └─P/Esc──> paused ──P/Esc──> playing
  └──────────────────────────────────────────── (paused から Q)
```

`window.__game.getState().scene` が返す値(文字列)は次の 8 つだけ。

| scene | 内容 |
| --- | --- |
| `title` | タイトル画面。道路が自動で流れる |
| `countdown` | ステージ開始前の 3・2・1(3.0 秒)。運転操作は無効、タイマー停止 |
| `playing` | 走行中。タイマー進行 |
| `paused` | 一時停止(`playing` からのみ入れる) |
| `stageclear` | ゴール後。車は自動で減速し、1.5 秒後にリザルトパネルを表示。パネル表示中の Enter で次へ |
| `timeup` | 時間切れ演出 2.5 秒(車は自動減速、運転入力は無効)。終了後 `gameover` |
| `gameover` | ゲームオーバー画面 |
| `ending` | 全ステージクリア画面(ランク表示) |

- 新しい run の開始(タイトルの Enter、`R`、ゲームオーバーの Enter)は、`score = 0`、ステージ = 開始ステージ(URL の `stage` パラメータ、なければ 1)、`crashes = 0`、`overtakes = 0` に初期化する。
- ステージ開始時(`countdown` に入る時)は、`speed = 0`、`playerX = 0`、`pos = 0`、`checkpointsPassed = 0`、`invulnTimer = 0`、`timeLeft = そのステージの開始時間` にし、交通車と路側物を配置し直す。`score`・`overtakes`・`crashes` は次ステージへ持ち越す。**残り時間は持ち越さない**(クリア時に得点へ換算する)。
- `countdown` は 3.0 秒(3 → 2 → 1 を各 1.0 秒)。終了と同時に `playing` に入り、画面中央に `GO!` を約 0.8 秒表示する。
- `paused` 中は、タイマー・車・交通車・アニメーション・音をすべて止める。

### 3.2 単位と定数

内部は「ワールド単位 u」で扱う。HUD は km/h と m に換算する。

| 名前 | 値 | 意味 |
| --- | --- | --- |
| W × H | 640 × 360 px | 論理解像度 |
| STEP | 1/60 秒 | 固定シミュレーション刻み |
| SEG_LEN | 200 u | 1 セグメントの長さ |
| ROAD_HALF | 2000 u | 道路の半幅。**playerX = ±1 が道路端** |
| LANES | 3 | レーン中心は x = −0.667 / 0 / +0.667(道路半幅を 1 とした値) |
| CAM_HEIGHT | 1000 u | カメラ高(起伏ぶんは加算) |
| FOV | 100° | CAM_DEPTH = 1 / tan(50°) ≈ 0.8391 |
| PLAYER_Z | CAM_HEIGHT × CAM_DEPTH ≈ 839.1 u | カメラからプレイヤー車までの距離 |
| DRAW_DIST | 200 セグメント | 描画するセグメント数 |
| RUMBLE_SEGS | 3 | 縞(明暗)が切り替わる周期。セグメント i の色帯 = floor(i / 3) mod 2 |
| MAX_SPEED | 12000 u/s | = 300 km/h。**1 km/h = 40 u/s** |
| 距離換算 | 144 u = 1 m | 12000 u/s = 83.3 m/s = 300 km/h と整合 |
| ACCEL | 2400 u/s² | アクセル加速(= 60 km/h/s) |
| BRAKE | 6000 u/s² | ブレーキ減速(= 150 km/h/s) |
| COAST | 1800 u/s² | アクセルもブレーキも押さない時の減速(= 45 km/h/s) |
| OFFROAD_DECEL | 6000 u/s² | コース外での追加減速(加算) |
| OFFROAD_LIMIT | 3000 u/s | = 75 km/h。コース外ではこれを超えている間 OFFROAD_DECEL が加わる |
| STEER_RATE | 2.0 | フル速度で 1 秒あたり playerX が動く量(速度に比例) |
| CENTRIFUGAL | 0.3 | 遠心力係数 |
| PLAYER_X_CLAMP | ±2.0 | playerX の範囲 |
| CRASH_SPEED_CAP | 2400 u/s | = 60 km/h。衝突後の速度上限 |
| CRASH_INVULN | 1.2 秒 | 衝突後の無敵(点滅)時間 |
| CRASH_PUSH | 0.12 | 衝突時に playerX を相手から離す量 |
| PLAYER_HIT_HALFW | 0.10 | プレイヤー車の当たり半幅(道路半幅を 1 とした値) |
| HIT_Z_WINDOW | 300 u | z 方向の当たり幅(相対 z の絶対値がこれ未満で重なり) |

変数の意味:

- `pos`: そのステージで走った距離(u)。カメラの z。`playerZ = pos + PLAYER_Z`。
- `speed`: u/s。`sp = speed / MAX_SPEED`(0〜1)。
- `playerX`: 道路半幅を 1 とした、プレイヤーの横位置。
- `distanceM = pos / 144`、`goalRemainingM = max(0, (goalZ − playerZ) / 144)`、`speedKmh = speed / 40`。

### 3.3 コース(道路)の作り方

各ステージのコースは「セクション表」から生成する。セクション = `[len, curve, dy]`(セグメント数, 曲率, 標高変化 u)。

**曲率(curve)**: セクション内のセグメント k(0 〜 len−1)について
`t = (k + 0.5) / len`、`e = clamp(min(t, 1 − t) / 0.25, 0, 1)`、`f = e² × (3 − 2e)`、`curve_k = curve × f`。
(前後 25% でなめらかに立ち上がり、中央で最大)。**正の curve = 右カーブ**(道路が画面右へ曲がる)。

**標高(y)**: セクション開始時の標高を y0 とし、セグメント境界 k(0 〜 len)の標高を
`y(k) = y0 + dy × (1 − cos(π × k / len)) / 2`。セグメント k の `p1.y = y(k)`、`p2.y = y(k+1)`。次のセクションの y0 は前のセクション終端の標高。**dy が正なら上り**。

**セグメント配列**: セクション表の合計セグメント数を N とし、その後ろに **300 本の直線・平坦セグメント**(curve = 0、y = 終端標高)を足した N + 300 本で 1 ステージ。
セグメント i は `p1.z = i × 200`、`p2.z = (i+1) × 200`、`index = i`。**ループはしない**(i ≥ N + 300 のセグメントは存在しない)。

**ゴール**: `playerZ ≥ N × 200` になった瞬間。**チェックポイント**: `playerZ ≥ cpSeg × 200`。ゲート(§6 の gate 画像)はそのセグメントの道路中央に描く。

### 3.4 描画アルゴリズム(疑似 3D)

古典的なセグメント投影方式で描く。この式で、道路・カーブ・起伏の見え方が全実装で揃う。

**投影**(ワールド点 `(worldX, worldY, worldZ)` とカメラ `(cameraX, cameraY, cameraZ)`)。結果の `camZ`・`scale`・`screenX`・`screenY`・`screenW` をその点(セグメントの p1 / p2)に保存する:

```
camX = worldX - cameraX;  camY = worldY - cameraY;  camZ = worldZ - cameraZ
scale   = CAM_DEPTH / camZ
screenX = round( W/2 + scale * camX * W/2 )
screenY = round( H/2 - scale * camY * H/2 )
screenW = round( scale * ROAD_HALF * W/2 )     // その深さでの道路の半幅(px)
```

**フレーム手順**:

0. 背景を描く(§3.4.1: y ≥ 180 を地面色で塗り、空 → 遠景 → (Should)近景の順に重ねる)。
1. `baseSeg` = セグメント `floor(pos / SEG_LEN)`、`basePercent = (pos mod SEG_LEN) / SEG_LEN`。`playerSeg` = セグメント `floor(playerZ / SEG_LEN)`、`playerPercent = (playerZ mod SEG_LEN) / SEG_LEN`。
2. `playerY = lerp(playerSeg.p1.y, playerSeg.p2.y, playerPercent)`。`cameraY = CAM_HEIGHT + playerY`、`cameraZ = pos`。
3. 初期化: `maxY = H`、`x = 0`、`dx = −baseSeg.curve × basePercent`。
4. `n = 0 … DRAW_DIST−1` について、`seg = segments[baseSeg.index + n]`(存在しなければ打ち切り):
   1. `seg.clipY = maxY` を記録する(描画をスキップする場合も必ず記録する)。
   2. `p1` を `cameraX = playerX × ROAD_HALF − x` で、`p2` を `cameraX = playerX × ROAD_HALF − x − dx` で投影する(`cameraY`・`cameraZ` は共通。p1 のワールド X・p2 のワールド X はともに 0)。
   3. `x += dx`、`dx += seg.curve`。
   4. `p1.camZ ≤ CAM_DEPTH`(カメラの背後)、`p2.screenY ≥ p1.screenY`(裏向き)、`p2.screenY ≥ maxY`(丘の陰に隠れている)のいずれかなら、道路を描かずに次へ。
   5. 描く: 地面(草)を画面全幅で `y ∈ [p2.screenY, p1.screenY]`、路肩の縞(道路の左右外側に幅 `screenW / 6`、色帯で 2 色交互)、道路面(2 色交互)、レーン区切り線(色帯が明のセグメントのみ。幅 `screenW / 32`、道路を 3 等分する 2 本)。台形は p1 の辺(screenX ± screenW)と p2 の辺で作る。
   6. `maxY = p1.screenY`。
5. スプライト(交通車・路側物・ゲート)を **遠い順(n が大きい方から)** に描く。各スプライトは所属セグメントの `clipY` より下を切り取る(丘の陰)。道路描画をスキップしたセグメントのスプライトも、投影値と `clipY` を使って描く。
6. プレイヤー車を描く(§3.4.2)。
7. 演出(煙など)、HUD、オーバーレイを描く。

**スプライトの描画規則**(交通車・路側物・ゲート共通): 対象の位置 `z`、横位置 `offset`(道路半幅を 1 とした値)、所属セグメント `seg`(`floor(z / SEG_LEN)`)について

```
percent  = (z mod SEG_LEN) / SEG_LEN                    // セグメント内の位置
sScale   = lerp(seg.p1.scale, seg.p2.scale, percent)
sX       = lerp(seg.p1.screenX, seg.p2.screenX, percent) + sScale * offset * ROAD_HALF * W/2
sY       = lerp(seg.p1.screenY, seg.p2.screenY, percent)      // 接地点
road_w   = sScale * ROAD_HALF * W/2                     // その深さの道路半幅(px)
destW    = worldW * road_w                              // worldW は §6 の表(道路半幅を 1 とした幅)
destH    = destW * (native高さ / native幅)
描画位置 = 左上 (sX - destW/2, sY - destH)                // 下辺中央を接地点に合わせる
```

`destW < 1 px`(負を含む)なら描かない。`sY − destH` から `sY` の範囲のうち `clipY` より下の部分は描かない。拡縮は補間なし(`imageSmoothingEnabled = false`)。

#### 3.4.1 背景の視差

- 論理座標で **地平線 y = 180**(H/2)を基準にする。y ≥ 180 は地面色(ステージの草の色)で先に塗る。
- レイヤーは空(`bg_sky_N`、640×180、上端 y = 0)、遠景(`bg_far_N`、640×96、下端 y = 180)、(Should)近景(`bg_near_N`、640×56、下端 y = 180)。すべて水平方向にシームレスにタイリングする画像で、オフセットぶんずらして 2 枚並べて描く。
- オフセット更新: 毎ステップ `layerOffset += curveAtPlayer × (Δpos / SEG_LEN) × k`(単位 px)。`curveAtPlayer = playerSeg.curve`。`k_sky = 0.15`、`k_far = 0.5`、`k_near = 1.0`。**右カーブ(curve > 0)では背景が左へ流れる**(描画は `x = −(layerOffset mod 640)` から 2 枚並べる)。

#### 3.4.2 プレイヤー車の描画

- 固定位置: 下辺中央 `x = 320`、下辺 `y = 354 − bounce`。`destW = 0.25 × 640 = 160 px`(`car_player` の native 40 px を 4 倍)、`destH = 88 px`。
- フレーム: 入力が「左」なら左フレーム、「右」なら右フレーム、それ以外は直進フレーム。
- `bounce`(px): `speed > 0` のとき 0〜1 の間で揺らす。コース外では 0〜3。乱数は見た目専用(`Math.random` 可。ゲーム用の seed 付き乱数を消費しない)。
- 無敵中(§3.5)は 0.1 秒周期で点滅(半分の時間だけ非表示)。

### 3.5 プレイヤーの運動

毎ステップ(dt = STEP)、`playing` のとき次の順で更新する。

```
1. 加減速
   throttle = ↑ または W が押されている
   brake    = ↓ または S が押されている
   if throttle: a = +ACCEL           // throttle と brake が同時なら throttle を優先
   elif brake:  a = -BRAKE
   else:        a = -COAST
   if |playerX| > 1 and speed > OFFROAD_LIMIT: a -= OFFROAD_DECEL     // 加算(スロットル中でも減速する)
   speed = clamp(speed + a*dt, 0, MAX_SPEED)

2. 操舵と遠心力
   steer = (→ または D ? +1 : 0) + (← または A ? -1 : 0)       // 両方押しは 0
   dxp   = dt * STEER_RATE * sp                                  // sp = speed / MAX_SPEED
   playerX += steer * dxp
   playerX -= dxp * sp * playerSeg.curve * CENTRIFUGAL           // 右カーブ(正)で左(負)へ押される
   playerX  = clamp(playerX, -2, 2)

3. 前進
   pos += speed * dt
```

- 速度 0 では操舵しても `playerX` は変わらない(`dxp = 0`)。
- **平衡速度の目安**: 操舵しきっても保てる速度は `sp ≈ 3.33 / curve`(curve 6 → 約 55%、curve 4 → 約 83%)。これより速いと外へ膨らむ。
- **衝突(クラッシュ)**: 交通車または路側物 solid に当たったら、`speed = min(speed, CRASH_SPEED_CAP)`、`crashes += 1`、`invulnTimer = CRASH_INVULN`、`playerX += (playerX ≥ 相手x ? +1 : −1) × CRASH_PUSH`。効果音 `sfx_crash`、煙(下記)。
  `invulnTimer > 0` の間は一切の衝突判定を行わない(点滅表示。`getState().invulnerable = true`)。衝突した相手には `hit = true` を立て、以後その相手とは衝突せず、追い越し得点も入らない。
  衝突後も操作は普通に効く(アクセルも即座に効く)。
- **煙**: 衝突の瞬間から 0.5 秒間、0.08 秒おきに `fx_smoke` の puff を自車の後部(画面座標で車の下辺中央付近)に 1 つずつ出す(計 6 個)。各 puff は 0.5 秒で 4 フレームを再生しながら、30 px/s で上へ漂い、2 倍の大きさで描く。

### 3.6 交通車

- 種類と諸元(速度は km/h 表記。内部は ×40 で u/s):

| 車種 | native サイズ | worldW | 当たり半幅 | 速度(km/h、一様乱数) |
| --- | --- | --- | --- | --- |
| sedan | 36×20 | 0.225 | 0.10 | 80〜110 |
| truck | 44×34 | 0.275 | 0.13 | 60〜80 |
| sports | 38×18 | 0.2375 | 0.10 | 120〜150 |

- **配置**(ステージ開始時に 1 度だけ。seed 付き乱数を使う): 台数 `count`(§3.3 表)、`spacing = (N − 160) / count`。
  `k = 0 … count−1` について
  `seg = round(60 + (k + 0.5) × spacing + (rand() − 0.5) × 0.6 × spacing)`、`z = seg × 200 + rand() × 200`、
  `lane` = k = 0 なら `randInt(3)`、それ以外は `(前の車の lane + 1 + randInt(2)) mod 3`(直前の車と同じレーンにならない)、
  車種は車種比で抽選、速度は上表の範囲で抽選。`x` = レーン中心。
- **移動**: 毎ステップ `z += speed × dt`。車線変更はしない。各レーンで、z が大きい車(先頭)から順に有効速度を決める: 同じレーンの前方 1000 u 以内に別の交通車がいれば、その車の有効速度と自分の速度の小さい方で走る(追い越し・重なりは起きない)。
  `z ≥ (N + 280) × 200` になった車は消える。
- **追い越し**: 前ステップの相対 z(`car.z − playerZ`)が正で、今ステップで 0 以下になり、かつその車の `hit` も `passed` も偽なら、`passed = true`、`overtakes += 1`、`score += 50`(§3.9)。
- **衝突判定**: `invulnTimer = 0` で、`|car.z − playerZ| < HIT_Z_WINDOW` **または** このステップで相対 z の符号が反転した(すり抜け防止)、かつ `|car.x − playerX| < PLAYER_HIT_HALFW + 当たり半幅`、かつ `car.hit = false` のとき衝突。
- 描画: §3.4 のスプライト規則(手前ほど大きい)。

### 3.7 路側物

- ステージ開始時に生成(seed 付き乱数)。`seg = 12, 18, 24, …`(6 おき)で `seg ≤ N + 60` の各セグメントについて、**左右それぞれ独立に**:
  - `r = rand()`。`r < 0.35` → solid(当たりあり)、`r < 0.75` → decor(当たりなし)、それ以外 → 置かない。
  - 種類は、実装した solid(または decor)の中から一様に選ぶ(Must は各ステージ solid 2 種・decor 1 種。Should で増やしてよい)。
  - `offset`(道路半幅を 1 とした値): solid は `1.45 + rand() × 0.55`(1.45〜2.0)、decor は `2.2 + rand() × 1.4`(2.2〜3.6)。左は負、右は正。
  - solid は `seg < 40` には置かない。ゲート(チェックポイント・ゴール)のセグメントの前後 ±4 セグメントにも置かない。置けなかった場合は何も置かない(decor に差し替えない)。
- solid の当たり判定は §3.6 と同じ式(当たり半幅は §6 の表)。当たると衝突(§3.5)。**コース外の走行可能帯 `1.0 < |playerX| < 約 1.15` は、衝突しない安全地帯**として残る(solid の offset が 1.45 以上のため)。
- 路側物は動かない。

### 3.8 タイムとチェックポイント

- `timeLeft`(秒)は `playing` の間だけ、毎ステップ `dt` ずつ減る(`countdown`・`paused`・`stageclear`・`timeup`・タイトルでは減らない)。HUD は `ceil(timeLeft)` を 2 桁ゼロ埋めで表示。
- チェックポイント通過: `timeLeft += 加算時間`(§3.3 表)、`score += 500`、`checkpointsPassed += 1`、`sfx_checkpoint`、画面中央上に `CHECKPOINT!` と `+18 SEC`(加算秒数)を 2.0 秒表示。
- `timeLeft ≤ 0`(かつそのステップでゴール条件を満たしていない)→ `timeLeft = 0` にして `timeup` へ。**同じステップでゴールとタイムアップが重なったらゴールを優先**。

### 3.9 スコア

| 得点源 | 点数 | 備考 |
| --- | --- | --- |
| 走行距離 | 1 点 / m | `Δpos / 144` を毎ステップ小数で積算。表示は切り捨て |
| 追い越し | +50 / 台 | §3.6 |
| チェックポイント | +500 | |
| ステージクリア: 残り時間 | +100 × floor(timeLeft) | ゴールした瞬間に加算 |
| ステージクリア: ステージボーナス | +1000 × ステージ番号 | 1000 / 2000 / 3000 |
| スレスレ(Should) | +20 | §8 S-07 |

- `score`(`getState()` の値・HUD)は、上の合計の **整数(切り捨て)**。`best` は `localStorage` に保存する最高スコア。
- **ランク**(エンディングの合計スコアで判定): `S ≥ 33000`、`A ≥ 28000`、`B ≥ 23000`、それ未満は `C`。
- ゲームオーバー・エンディングの時点で `score > best` なら、`best` を更新して保存し、画面に `NEW BEST!` を出す。HUD の BEST 表示は `max(best, score)`。

### 3.10 乱数

- seed 付き乱数(mulberry32 など)を使う。seed は URL の `?seed=<整数>`、なければページ読み込み時に 1 つ決めて(例: `Date.now()` 由来)ページの寿命の間ずっと使う(同じページ内でのリスタートは同じ配置になる)。
- ステージ開始時に `rng = seededRng(seed XOR (ステージ番号 × 0x9E3779B1))` を作り、交通車 → 路側物の順に配置する。同じ seed・同じステージなら、**同一実装内で**配置が完全に同じになること。
- 配置後のシミュレーションで乱数を使わない(入力が同じなら結果が同じ)。見た目専用の揺れは別の乱数(`Math.random` 可)。

### 3.11 ステージクリア・ゲームオーバー・エンディング

- **ステージクリア**: ゴール条件で `stageclear`。得点(残り時間ボーナス+ステージボーナス)を即加算。運転入力は無効で、車は `−3000 u/s²` で自動減速して前進し続ける。BGM を止めて `sfx_goal` を鳴らす。ゴール通過から 1.5 秒後にリザルトパネルを出し、パネル表示中の Enter(または Space)で:
  - ステージ 1・2 → 次のステージの `countdown` へ。
  - ステージ 3 → `ending` へ。
- **タイムアップ**: `timeup`(2.5 秒)中は画面中央に大きく `TIME UP`、車は `−6000 u/s²` で自動減速。BGM を止めて `sfx_timeup` を鳴らす。終了後 `gameover`。
- **ゲームオーバー画面**: `GAME OVER`、`REACHED STAGE n`、`SCORE`、`BEST`、`NEW BEST!`(更新時)、`ENTER: RETRY   ESC: TITLE`。
- **エンディング画面**: `ALL CLEAR!`、合計スコア、ランク(大きな 1 文字)、`BEST`、`NEW BEST!`(更新時)、`PRESS ENTER`。

### 3.12 リザルトパネルの内容(ステージクリア)

```
   STAGE 1 CLEAR!
   TIME LEFT   23  X100  = 2300
   STAGE BONUS           = 1000
   SCORE                 = 012345
   PRESS ENTER
```

(ステージ 3 でも最後の行は `PRESS ENTER` で、押すと `ending` へ行く。)

## 4. 操作

| 入力 | 動作 |
| --- | --- |
| `↑` / `W` | アクセル(押している間) |
| `↓` / `S` | ブレーキ(押している間) |
| `←` `→` / `A` `D` | ハンドル |
| `Enter` / `Space` | 決定(タイトル開始、リザルト送り、ゲームオーバーからのリトライ)。`keydown` の `repeat` は無視 |
| `P` / `Esc` | 一時停止 / 再開(`playing` と `paused` のみ)。`gameover` / `ending` では `Esc` はタイトルへ |
| `R` | 最初からやり直し(開始ステージ、score 0)。`countdown` / `playing` / `paused` / `gameover` / `ending` で有効 |
| `Q` | `paused` と `gameover` からタイトルへ戻る |
| `M` | ミュート切り替え(全画面で有効) |
| `F`(Should) | フルスクリーン切り替え |

- キーは `KeyboardEvent.code`(`ArrowUp`, `KeyW`, `Enter`, `Space`, `KeyP`, `Escape`, `KeyR`, `KeyQ`, `KeyM` …)で判定する。
- `window` の `keydown` / `keyup` を購読する。矢印キーと Space は `preventDefault()` でページスクロールを防ぐ。`window` の `blur` と `visibilitychange`(非表示)で押下状態をすべてクリアする(キー押しっぱなしのまま固まらない)。
- `paused` 中は運転キーを無視。`stageclear` / `timeup` 中も運転入力は無視。
- **タッチ(Should)**: タッチ端末(`(pointer: coarse)`)でだけ、半透明のボタンを出す。左下に左右ボタン(ハンドル)、右下にアクセルとブレーキ。矢印は図形で描く(DOM ボタン可)。押している間だけ有効(ポインタイベント)。タイトル・リザルトは画面タップで決定。

## 5. 画面と UI

### 5.1 レイアウトの基準

- `<canvas id="game" width="640" height="360">` を画面中央に置く。ページ背景は黒に近い暗色。
- CSS でアスペクト比 16:9 を保って **ウィンドウに収まる最大サイズ**に拡縮する(`width: min(100vw, 100vh * 16 / 9)` 相当)。余白は暗色でレターボックス。スクロールバーを出さない(`body { margin: 0; overflow: hidden; }`)。
- `image-rendering: pixelated`(併記で `crisp-edges`)。canvas のバッキングストアは常に 640×360(`devicePixelRatio` で解像度を上げない)。描画は `imageSmoothingEnabled = false`。
- モバイル縦幅(375×667 など)でも canvas 全体が見える(縮小されるだけ)。タッチボタンは canvas の下の余白か、canvas 上に重ねて表示。

## 6. 見た目・音・アセット

### 6.1 方針

- **画風**: 16 ビット時代のアーケードレーサー風ピクセルアート。輪郭ははっきり、影は 1〜2 段階のトーン。**ステージごとに色調をはっきり変える**(§3.3 表の「時間帯・色調」)。
- **配色**: ステージ 1 は橙・桃・青緑(海)、ステージ 2 は紫・藍・深緑(松)、ステージ 3 は黒・濃紺・マゼンタ・シアン(ネオン)。道路・草・路肩の縞は各ステージで 2 色ずつの明暗ペアを作り、縞が視認できる(隣り合う色の輝度差が明確な)こと。
- **音**: 入れる。すべて Web Audio で合成。ミュートは `M`。
- **アセットは実装担当がゼロから自作する**(他の実装・他ゲーム・外部素材のコピー禁止)。本書にはピクセル配列・色コード・音のデータを書かない。サイズと最低ラインだけを決める。
- 画像は「コード内のピクセル配列(文字列やバイト列)を起動時に offscreen canvas へ描く」形を推奨。PNG ファイルとして `dist/` に置いてもよいが、自作したものに限る(相対パス参照)。

| `bgm_1` | ステージ中の BGM(`countdown` と `playing`(と `paused` で一時停止)の間) | 120〜140 BPM、**8 小節以上のループ**、ベース+リード+ドラム(ノイズ)の 3 パート以上 | Must |
| `bgm_2` `bgm_3` | ステージ 2・3 専用 BGM(曲調・テンポを変える。S2: 130〜145 BPM の短調、S3: 140〜160 BPM のアルペジオ主体) | | Should(実装した場合、ステージごとに切り替える) |
| `sfx_engine` | エンジン音(連続音) | 2 つ以上の発振器(のこぎり波+矩形波など)をローパスに通し、**周波数 `engineHz = 60 + 140 × sp`(Hz)**、ゲイン 0.05 + 0.07 × sp。`countdown` はアイドル(sp = 0)。`title` / `paused` / `gameover` / `ending` では停止 | Must |
| `sfx_beep` | カウントダウン 3・2・1 | 440 Hz、0.15 秒 | Must |
| `sfx_go` | `GO!` | 880 Hz、0.4 秒 | Must |
| `sfx_checkpoint` | チェックポイント | 明るい上昇 2〜3 音 | Must |
| `sfx_crash` | 衝突 | ノイズ+低音の減衰(0.4 秒程度) | Must |
| `sfx_goal` | ゴール | 短いファンファーレ(1〜2 秒) | Must |
| `sfx_timeup` | 時間切れ | 下降する音列 | Must |
| `sfx_menu` | タイトルの決定・リザルト送り | 短いブリップ | Must |
| `sfx_overtake` | 追い越し | 短い風切りまたはピッ | Should |
| `sfx_offroad` | コース外走行の砂利音(ループ) | ノイズ+ローパス。コース外の間だけ鳴らす | Should |
| `sfx_timewarn` | 残り 10 秒以下で毎秒 1 回 | 短いティック | Should |
| `jingle_title` | 初回キー入力時のタイトルジングル、クリア時のジングル | | Should |

- マスターゲイン 0.5、BGM は相対 0.35、SFX は相対 0.6、エンジンは相対 0.4 を目安に(音割れしない)。
- `AudioContext` は最初のユーザー操作(keydown / pointerdown)で生成または `resume()` する。生成前は `getState().audio.state = 'none'`。
- `paused` では `AudioContext.suspend()` し、再開で `resume()`。ミュート時はマスターゲインを 0 にする(状態の保存は §7.2)。

### 6.5 アセットギャラリー(検証用・Must)

`index.html?gallery=1` で、ゲームの代わりに **アセットギャラリー**を表示する(スクロール可の通常 HTML ページ、DOM 使用可)。

- §6.2 の画像アセット(Must)と、実装した Should の画像アセットをすべて並べる。各アセットは 1 つの `<canvas>` に **全フレームを左から右へ並べて**(2 倍以上の見やすい拡大で)描き、`data-asset-id`(表の ID)、`data-frames`(フレーム数。`font_pixel` はグリフ数)、`data-frame-w`、`data-frame-h`(native px)の属性を付ける。canvas のすぐ下に ID を文字(DOM テキスト可)で表示する。
- `font_pixel` は、全グリフを並べた 1 つの canvas として表示する。
- 音アセットは `<button data-sound-id="bgm_1">bgm_1</button>` のように、実装した ID(§6.4)ぶんのボタンを並べる。押すとその音を再生する(BGM・エンジンは 3 秒程度のプレビューでよく、再度押すか 3 秒後に止まる)。
- ボタン `data-sound-id="mute"` でミュートを切り替えられる。

## 7. 技術要件

### 7.1 ゲームループ(フレームレート非依存)

- `requestAnimationFrame` で描画し、シミュレーションは **固定ステップ `STEP = 1/60` 秒**のアキュムレータ方式で進める。フレーム間隔は `min(実経過, 0.1 秒)` で丸め、1 フレームあたり最大 6 ステップまで(超えたぶんは捨てる)。
- タイマー・速度・移動・演出タイマー(`invulnTimer`、バナー、`countdown` など)はすべてステップ数(または STEP の積算)で進める。30fps でも 144fps でも、同じ入力で同じ結果(加速の秒数、`timeLeft` の減り方)になること。
- タブが非表示の間は進めない(rAF が止まる前提。復帰時に大きく進まない)。

### 7.2 永続化

- `localStorage` のキーは `sunset-rush:v1`、値は JSON `{ "best": <数値>, "muted": <真偽> }`。
- 読み書きはすべて `try/catch`。`localStorage` が使えない・例外を投げる環境でもゲームが普通に動く(保存されないだけ)。
- `best` はゲームオーバー / エンディング時に更新して保存。`muted` は `M` を押すたびに保存し、次回起動時に復元する。

### 7.3 URL パラメータ(検証用)

| パラメータ | 動作 |
| --- | --- |
| `seed=<整数>` | 乱数の seed を固定(§3.10) |
| `stage=<1〜3>` | 新しい run の開始ステージ(タイトルで Enter を押した時、`R` の時)。範囲外・不正値は 1 |
| `debug=1` | `window.__game.debug` を有効化(§7.4)。右下に FPS を出す(Should) |
| `mute=1` | 起動時にミュート状態にする(`localStorage` には保存しない) |
| `gallery=1` | アセットギャラリーを表示(§6.5) |

### 7.4 検証フック(`window.__game`)

`debug` の有無にかかわらず、ゲーム画面(`gallery` でないとき)では `window.__game` を公開し、`getState()` を持たせる。

```
window.__game.getState() -> {
  scene:             'title'|'countdown'|'playing'|'paused'|'stageclear'|'timeup'|'gameover'|'ending',
  seed:              number,
  stage:             1|2|3,
  score:             number,          // 整数(HUD と一致)
  best:              number,
  timeLeft:          number,          // 秒(小数)
  speedKmh:          number,          // 0〜300(小数可)
  playerX:           number,          // 道路半幅を 1 とした値(道路端 ±1)
  distanceM:         number,          // pos / 144
  goalRemainingM:    number,
  checkpointsPassed: number,          // そのステージで通過した数 0〜2
  overtakes:         number,          // run 全体の累計
  crashes:           number,          // run 全体の累計
  invulnerable:      boolean,
  trafficTotal:      number,          // そのステージの交通車の総数
  layoutHash:        string,          // 交通車・路側物の配置から計算した文字列(同一実装内で seed とステージが同じなら同じ値)
  muted:             boolean,
  rank:              'S'|'A'|'B'|'C'|null,   // ending のときだけ
  audio: { state: 'none'|'running'|'suspended'|'closed', bgm: string|null, engineHz: number }
}
```

- `audio.bgm`: `countdown` / `playing` / `paused` のとき再生中の BGM の ID(`bgm_1` など)、それ以外の scene では `null`。
- `audio.engineHz`: 現在エンジン音に設定している基本周波数(Hz)。`countdown` / `playing` / `stageclear` / `timeup` のとき `60 + 140 × sp`、それ以外の scene では 0。

`?debug=1` のときだけ `window.__game.debug` を持たせる:

| メソッド | 動作 |
| --- | --- |
| `warp(m)` | `countdown` / `playing` で `pos = m × 144`(0 以上、`goalZ − 3000` 以下にクランプ)。それより後ろにある交通車は `passed = true`、通り過ぎたチェックポイントは加算なしで通過済みにする(得点・時間は動かさない)。`speed`・`playerX` は変えない |
| `setTime(sec)` | `timeLeft = sec` |
| `setPlayerX(x)` | `playerX = x`(±2 にクランプ) |
| `setSpeedKmh(v)` | `speed = clamp(v, 0, 300) × 40` |

### 7.5 その他

- コンソールエラー・未処理例外・失敗リクエスト(404 など)を出さない。外部ドメインへのリクエストを出さない。
- 描画は `getContext('2d', { alpha: false })`。1 フレームの処理を 16ms 以内に収める(DRAW_DIST = 200 の道路+スプライトで十分間に合う想定)。
- 道路の縞にセグメント間の継ぎ目(1px の隙間・ちらつき)が見えないこと(隣接セグメントを 1px 重ねて塗る、座標を整数に丸めるなど)。
- `dist/` の構成は自由(例: `index.html`、`js/*.js`)。すべて相対パスで参照する。
- 推奨の実装順(Must を先に満たし、Should はその後): ① 道路の投影と描画(カーブ・起伏)→ ② 走行の物理と入力 → ③ 交通車・路側物・衝突 → ④ シーン遷移・HUD・スコア・タイマー → ⑤ アセット(画像)の制作と差し込み → ⑥ 音 → ⑦ 検証フック・ギャラリー → ⑧ Should の演出。

## 8. 受け入れ基準

ブラウザ(Chromium、Playwright 可)で観察して合否を判定する。`?debug=1` と `window.__game` を使ってよい。数値の許容範囲は理論値からの誤差込み。

### Must

**起動・公開・表示**

1. `dist/index.html` が存在し、`dist/` を HTTP 静的サーバのルートで配信しても、サブパス(例: `/x/y/dist/`)で配信しても開ける。404 になるリクエストがなく、参照はすべて相対パスである。
2. 読み込みからタイトル → 3 ステージ → エンディング(またはゲームオーバー)まで通して、コンソールエラー・未処理例外・失敗リクエストが 0 件で、外部ドメインへのリクエストが 0 件である。
3. canvas は論理解像度 640×360。ビューポート 1280×720 / 1920×1080 / 375×667 のいずれでも、16:9 を保って全体が見え、スクロールバーが出ず、ピクセルがにじまない(`image-rendering: pixelated`)。
4. タイトル画面に、ロゴ画像(`logo_title`)、点滅する `PRESS ENTER`、`BEST` の値、操作説明が表示され、背景で道路が自動で流れる(時間をおいた 2 枚のスクリーンショットで道路の縞・背景の位置が変わっている)。

**遷移・運転**

5. タイトルで Enter(または Space)を押すと `countdown` になり、`3` `2` `1` が 1 秒ずつ大きく表示され、ステージ名(`STAGE 1` / `SEASIDE`)が出る。この間に `↑` を押しても `speedKmh` は 0 のままで、`timeLeft` は 30 から減らない。
6. カウントダウンが終わると `playing` に入り、`GO!` が約 0.8 秒出る。その後 `timeLeft` が 30 から 1 秒に約 1 ずつ減る(`playing` 開始 5 秒後に 25.0 ± 0.3)。
7. アクセル: `playing` 開始直後から `↑` を押し続けて 3.0 秒後の `speedKmh` が 170〜190(理論値 180)。速度は 300 を超えない。
8. ブレーキ: `setSpeedKmh(200)` の後 `↓` を 1.0 秒押し続けると、`speedKmh` が 140〜160 減る(理論値 150 減)。
9. 惰性: `setSpeedKmh(200)` の後、何も押さずに 2.0 秒経つと `speedKmh` が 104〜116(理論値 110)。
10. 操舵: 走行中に `→`(または `D`)を押している間 `playerX` が増え、`←`(または `A`)で減る。速度 0 では押しても `playerX` は変わらない。
11. 遠心力: ステージ 1 で `warp(765)`(右カーブ区間)し、`setSpeedKmh(200)`、`playerX = 0` から、操舵なし・`↑` 押しっぱなしで 1.0 秒後に、`playerX` が `−0.5` 以下(負方向)に動いている。
12. コース外: `setPlayerX(1.05)` にして `↑` 押しっぱなし・操舵なしで衝突が起きない状況なら、3 秒後の `speedKmh` が 70〜80(コース外の上限 75 付近)に落ち着く。画面上で道路の外側(草の面)を走っている。
13. 道路のカーブと起伏: ステージ 1 を走ると、道路が左右に曲がって見える。上り坂の頂上では向こう側の道路が隠れ、上り・下りで道路の消失位置(画面上の高さ)が変化する(複数地点のスクリーンショットで確認できる)。
14. 視差: カーブ中(例: `warp(765)` 付近)に、遠景(`bg_far_1`)と空が横へ流れる。右カーブでは左へ流れる。`↑` などを離して `setSpeedKmh(0)` にして止まると、流れも止まる。
15. 道路の縞(路肩の 2 色交互、草・路面の明暗)が見え、セグメント間の継ぎ目・隙間がない。3 セグメントおきに明暗が入れ替わる縞が、奥へ向かって細くなって見える。

**交通車・衝突**

16. 交通車が 3 車種(`car_sedan` / `car_truck` / `car_sports`)とも道路上に現れ、遠いほど小さく描かれ、3 車線のいずれかの上を走る(ステージ 1 を 30 秒程度走って 3 車種すべてを目視で確認できる)。`trafficTotal` がステージ 1 で 36、ステージ 2 で 54、ステージ 3 で 72。
17. 追い越し: 交通車と衝突せずに追い越すと、`overtakes` が 1 増え、`score` に 50 点が加わる(距離点とは別に、その瞬間 +50 のジャンプが観測できる)。衝突した車を追い越しても加算されない。
18. 交通車との衝突: 交通車に当たると、直後の `speedKmh` が 62 以下、`crashes` が 1 増え、`invulnerable` が約 1.2 秒 true、車が点滅し、煙(`fx_smoke`)が出る。無敵中は他の物に当たらない。ゲームは続行できる。
19. 路側物との衝突: ステージ 1 で `setPlayerX(1.8)` 付近を走って路側の solid(ヤシの木・岩)に当たると、18 と同じ反応が起きる(`|playerX| ≥ 約 1.3` で走ると当たる)。
20. 路側物の表示: 各ステージで、そのステージ固有の solid 2 種と decor 1 種(§6.2)が道路の両側に現れる(ステージ 1: ヤシ・岩・低木、ステージ 2: 松・大岩・シダ、ステージ 3: 街灯・ネオン看板・ビル)。solid は道路端より外側に置かれ、decor はさらに遠い。

**タイム・チェックポイント・ステージ**

21. `timeLeft` は `playing` の間だけ減る。一時停止中・カウントダウン中・`stageclear` 中は 2 秒待っても値が変わらない。
22. チェックポイント: ステージ 1 で `warp(990)`、`setSpeedKmh(200)`、`↑` 押しっぱなしで走ると、約 1 秒以内に `timeLeft` が 18 増え、`score` に 500 が加わり、`checkpointsPassed` が 1 になり、画面に `CHECKPOINT!` と `+18 SEC` が約 2 秒出る。道路上にゲート(`gate_checkpoint`)が見えている。
23. タイムアップ: `setTime(2)` して 2 秒待つと `timeup`(`TIME UP` の大表示)になり、その約 2.5 秒後に `gameover` になる。ゲームオーバー画面に `GAME OVER`、`REACHED STAGE 1`、`SCORE`、`BEST` が表示される。
24. ゴール: ステージ 1 で `warp(2950)`、`setSpeedKmh(200)`、`↑` 押しっぱなしで走ってゴールすると、`stageclear` になり、`score` が「ゴール直前の値 + 100 × floor(残り秒) + 1000」だけ増え(距離点ぶんの小差は許容)、1.5 秒後に §3.12 のパネルが出る。ゴールのゲート(`gate_goal`)が見えている。
25. パネル表示中に Enter を押すとステージ 2 の `countdown` になり、`stage = 2`、`goalRemainingM` が約 3594(± 2)、`timeLeft` が 32、`trafficTotal` が 54。`score` は引き継がれ、`timeLeft` は持ち越されない。
26. ステージ 2 とステージ 3 で、空・遠景・路面・草・路側物の見た目が、ステージ 1 とはっきり違う(スクリーンショットの支配色が、S1 = 橙〜桃、S2 = 紫〜藍、S3 = 黒〜濃紺+ネオン色)。ステージ 3 の `goalRemainingM` は開始時に約 4194(± 2)、`timeLeft` は 32。
27. ステージ 3 をクリアすると `ending` になり、`ALL CLEAR!`、合計スコア、ランク文字(`S`/`A`/`B`/`C`)、`BEST` が表示され、`getState().rank` が §3.9 の閾値どおり。Enter でタイトルに戻る。
28. スコア: 追い越し・チェックポイントがない距離走行で、`score` が走行距離(m)とほぼ同じペースで増える(1 点 / m。`score ≈ floor(distanceM)`)。HUD の SCORE と `getState().score` が一致する。

**一時停止・リスタート・音・保存**

29. `P`(または `Esc`)で `paused` になり、`PAUSED` のオーバーレイが出る。2 秒待っても `timeLeft`・`distanceM` が変わらず、交通車も動かない。もう一度 `P`(または `Esc`)で `playing` に戻る。`paused` 中に `R` でリスタート、`Q` でタイトルへ戻れる。
30. `R` で(`playing` / `paused` / `gameover` / `ending` から)最初からやり直せる: `stage` = 開始ステージ、`score` = 0、`overtakes` = 0、`crashes` = 0、`countdown` から始まる。`gameover` では Enter でもリトライでき、`Esc` / `Q` でタイトルへ戻る。
31. `M` で `muted` が切り替わり、HUD の `[M] SOUND ON/OFF` 表示が変わる。リロード後も状態が保たれる(`localStorage`)。`mute=1` パラメータで起動時ミュートになる。
32. ベストスコア: ゲームオーバー(またはエンディング)で `score` が保存済みの `best` を上回ると `NEW BEST!` が出て、リロード後のタイトルの `BEST` がその値になる。`localStorage` の読み書きが例外を投げる状態(`Storage.prototype.getItem` / `setItem` を差し替え)でも、コンソールエラーなしでゲームが最後まで動く。
33. HUD: `playing` 中に、`TIME`(数字)、`SCORE`(6 桁)、`STAGE n/3`、`BEST`、速度と `KM/H`、進捗バー(チェックポイントの縦線・ゴールの旗・現在位置マーカー)、`PASSED n`、`[M] SOUND ...` がすべて表示される。`timeLeft ≤ 10` で時間の数字が赤く点滅する。
34. 音: 最初のキー入力後に `audio.state` が `running` になる。`countdown` と `playing` の間は `audio.bgm` が `null` でない(`stageclear` / `timeup` / `title` では `null`)。`engineHz` は `countdown` 中(速度 0)で 60、`setSpeedKmh(150)` で約 130、300 km/h で 200(± 10)と、速度に比例して上がる。`title` と `paused` では 0。ミュート中は音が鳴らない(マスターゲイン 0)。
35. 入力の堅牢性: 矢印キーと Space でページがスクロールしない。キーを押したままウィンドウの `blur` を起こすと、押下状態がリセットされる(車が加速し続けない)。`keydown` の `repeat` で決定が連打されない。

**再現性・アセット・品質**

36. `?seed=42` で 2 回読み込んだ場合、同じステージの `layoutHash` が一致する。`?seed=43` では異なる値になる。同じページでの `R` リスタートでは、同じステージの `layoutHash` が変わらない。
37. フレームレート非依存: CDP の CPU スロットリング等で描画が 30fps 前後まで落ちても、7 の「3.0 秒アクセルで 170〜190 km/h」と 6 の「5 秒後に `timeLeft` が 25.0 ± 0.3」が同様に成り立つ。
38. `?gallery=1` でアセットギャラリーが開き、§6.2 の Must 画像すべて(`car_player` … `fx_smoke`、`bg_sky_1..3`、`bg_far_1..3` を含む)に対応する `data-asset-id` 付き canvas があり、`data-frames` が表の最低フレーム数以上で、実際に絵が描かれている(空でも全面同色でもない)。`font_pixel` は `A`〜`Z`・`0`〜`9` が判読できる。音は §6.4 の Must の ID すべてに `data-sound-id` 付きボタンがあり、押すとエラーなく鳴る。
39. 必要なアセットが一覧どおりに用意され、画面に表示される: ゲーム中に、`car_player` の 3 フレーム(直進・左・右)、3 車種の交通車、各ステージの空・遠景・路側物、チェックポイント/ゴールのゲート、`fx_smoke`、`logo_title`、`font_pixel` の文字が実際に描かれる(ステージごとのスクリーンショットで確認できる)。
