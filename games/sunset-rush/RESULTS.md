### EVAL.md からの逸脱(測れなかった項目・手順の変更)

1. **自動運転ボット(§1.3)**: EVAL の規則どおりだと、`playing` 開始直後(速度 0、`playerX = 0`、`|err| = 0.333 ≥ 0.15`)にブレーキ+右操舵となり、速度 0 では操舵が効かないため永久に停止する(5 実装すべてで確認)。**80 km/h 未満では ↓ の代わりに ↑ を押す**規則を足した。それ以外は EVAL どおり。合成キーの対照テスト(合成 `ArrowUp` 0.5 秒で `speedKmh` が 30 に上がる)は全実装で成立したので、ボットは合成イベントのまま使った。
2. **M04(タイトルの道路の変化)**: 180 km/h(7200 u/s)の自動走行では縞の 1 周期(6 セグメント = 1200 u)をちょうど 1.0 秒で 6 周期進むため、0.5 秒と 1.5 秒の 2 枚では縞が一致する。実測でも low 1.9% / high 2.6% / max 2.1% と閾値 5% を下回った(medium 12.5%、xhigh 20.8% は交通車・路側物の差で超えた)。**0.5 秒と 0.75 秒(1.5 周期ずれ)の 2 枚も撮り**、どちらかで 5% 以上なら合格とした(0.25 秒差では 5 実装とも 53〜89%)。
3. **M13 / M14 / M22 / M24 の撮影前の待ち**: `playing` 開始直後に `warp` すると、カウントダウンのステージ名と `GO!` が画像に重なり、M14 では空の帯 A の推定を乱した。全実装で **`playing` 開始から 2 秒待ってから** `warp` するように変えて取り直した(`raw/log2-*.txt`)。
4. **W ルートの `Enter` の時刻**: EVAL は「パネル表示の 1.7 秒後」だが、M21(3)の `stageclear` 開始 2.1 秒後の `timeLeft` と、S-18 用のパネル連写(1.5〜2.2 秒)を先に取るため、**`stageclear` 開始から約 2.45 秒後**に押した。
5. **M17 の衝突相手の抜き去り**: 別の手順にせず、M18 の手順(衝突直後から無敵中は `setPlayerX(1.8)`・`setSpeedKmh(250)`)の最初の 0.3 秒の `overtakes` の増分で見た(EVAL は 200 km/h)。5 実装とも増分 0。
6. **M18 の無敵時間**: max の初回測定で、無敵が切れたのと同じステップで路側物に再衝突し、`invulnerable = false` のフレームが観測されずに 3.6 秒と記録された。「`invulnerable` が false になった最初のフレーム、または次の衝突が起きたフレーム」を無敵の終わりとする判定に直し、全実装を取り直した(全実装 1.199〜1.201 秒)。
7. **M34 の `engineHz`**: `setSpeedKmh(150)` / `(300)` を 1 回だけ呼ぶのではなく、毎フレーム指定し続けて 0.25 秒後に読んだ(惰性で速度が下がるのを避けるため)。
8. **M38 / O-7 の「描画済み」**: low の `font_pixel` は白一色のグリフ+透明で、不透明画素の色が 1 色しかない。「全面同色でない」を「不透明画素が 2 色以上、または透明画素と不透明画素が混在」と解釈して合格にした。
9. **S-02(近景の視差)**: 帯 C(y = 130〜176)は遠景(y = 84〜180)と重なり、xhigh と max では遠景と同じ −29 / −30 px と推定された。M14 の走行中 2 枚を行の帯ごと(y = 100〜178 を 5 帯)に推定し直し(`eval/scripts/s02-bands.mjs`、±90 px)、「空 < 遠景 < 近景(最下段 y = 170〜178)」の 3 段に分かれ、近景が遠景の 1.5 倍以上なら合格とした。5 実装とも 空 −9 / 遠景 −29〜−31 / 近景 −60〜−71 px で合格。
10. **追加測定(判定の根拠を補うため、全実装に同じ手順で追加)**: S-05 の画面シェイク(`S05X`: 衝突直後の各フレームで空の帯の横ずれを推定)、S-18 のロゴの動き(`S18X`: ロゴ帯の縦ずれを推定)、S-04 のタイヤ部分の 8 倍拡大連写(`S04Z`)、エンディング画面の 3 枚連写(`M27X`。点滅する `PRESS ENTER` の確認)、ゲームオーバー画面の 6 枚連写(`M32X`。high の `NEW BEST!` が 0.3 秒周期で点滅し、M32 の 1 枚に写らなかったため)。
11. **S-11**: `setTime(10.5)` 後 3 秒の出力タップ RMS からは、BGM の拍に埋もれて 1 秒周期の山を分離できなかった。ボタンの有無と、残り 10 秒以下で整数秒が変わるたびに `sfx_timewarn` を鳴らすコード(5 実装とも存在)で判定した。
12. **実行の並列度**: 機能テストは 2 実装ずつ並列(low+medium、high+xhigh、max 単独)で流した。時刻に敏感な値はページ内の rAF で取っているため影響は小さいと判断した。パフォーマンス(O-4)は他の負荷なしで 1 実装ずつ順に流した。1 回目の平均が他の回と 20% 以上違う状況はなく、再測定はしていない。
13. **エラーの「全テスト合計」**: EVAL §1.1 は全テスト合計も記録するとしているが、エラー収集を集計したのは上記のページ(起動・W ルート・B ルート・ギャラリー・`localStorage` 例外化・`F`)だけで、その他のテストのページは集計していない(未計測)。

## 所見

### 実装の違い

- **動作・完成度**: 5 実装とも Must 42 件すべて合格し、W ルート・B ルートともエンディングまで到達した。エラーも 0 件。物理・得点・タイマーの数値は 5 実装でほぼ一致した(差は測定のフレーム誤差の範囲。M17・M22・M24・M28 の得点・時間の増分は完全に同じ。B ルートでも low と max、medium・high・xhigh がそれぞれ同じ結果)。差は Should と見た目に集中した。
- **ゲームとしての手触り・面白さ**: 操作の物理は同一なので、差はフィードバックの量から来る。スレスレ得点(`NEAR MISS +20`)は全実装にある。衝突時のシェイク・火花・傾きは medium 以上にある。low は衝突しても点滅と煙だけで、手応えが薄い。
- **アセット(画づくり・アニメーション・音)の違い**: effort が上がるほど描き込みが増えた。low はフラットな矩形の車、medium で太陽・海の作り込み、high でグローとタイヤアニメが入り、xhigh / max ではディザの空・発光・細部の陰影まで入る。音は medium 以上で Should の音がすべてそろい、high 以上で BGM が 16 小節になった(low / medium は 8 小節)。
- **コード品質(構造・読みやすさ・テスト)**: low は `main.js` 1 本に集約(dist 5 ファイル・1,113 行)、medium は 7 ファイル、high は 16 モジュール(const / course / render / game など)、xhigh と max は 20〜21 モジュール(`world` / `sim` / `hud` / `input` / `music` / `art/*` に分割)。xhigh と max は `dist/` の外に検証用スクリプト(xhigh 16 本、max 28 本+`package.json`)を置いている。評価担当はそれらを実行していない。
- **仕様の解釈の違い**:

### effort による差

- **差が出た点 / 出なかった点**: Must(42/42)・エラー件数(0)・運転の数値・FPS(平均 59.5〜60.05)には差がなかった。Should は low 11 → medium / high / xhigh 17 → max 18。主観評価は画づくりが 3 → 4 → 4 → 5 → 5、演出が 4 → 4 → 4 → 5 → 5 と、effort に沿って上がった。コストは tokens が 5.7 倍(127k → 728k)、所要時間が 11 倍(10 分 → 114 分)。
- **effort を上げる価値があった項目**: low → medium で Should が 6 件増えた(タッチ UI・砂煙と砂利音・ジングル・自動ポーズ・火花とシェイク・信号ライト)。コスト増(tokens 1.3 倍)に対して最も効果が大きい。medium → high では Should の件数は同じで、タイヤアニメ・グロー・16 小節 BGM が加わり、S-15 が部分実装になった。high → xhigh / max では見た目(画づくり・演出・UI)が 4 → 5 に上がった一方、tokens は 2.3〜2.8 倍、時間は 3〜4 倍かかった。xhigh と max の差は、S-15 の解釈とカウントアップの有無程度。
- **自己申告と実測のズレ(自己チェックの正直さ)**:
  - low: 未実装の Should(タッチ・砂煙 / 砂利音・火花・ジングル・自動ポーズ・フェード)を README で正直に列挙しており、実測と一致した。ただし「衝突演出」のシェイクはコードにあるのに、実測では検出できなかった。
  - medium: README は「S-01〜S-07 … を実装」と書く一方、同じ README で `car_player_wheel`(S-04)を未実装としており、記述が一部矛盾する。実測は S-04 だけ不合格。
  - high: S-15 を「一部(非表示時のみ)」、S-18 をロゴのみと申告しており、実測と一致した。
  - xhigh: S-15 を「合格(自動)」としているが、根拠は非表示でのポーズで、合成 `blur` では止まらない設計であることも README に明記されている。EVAL の判定では不合格。
  - max: Should 全件合格の申告と実測が一致した。

### 仕様書の問題点

- **タイトルの自動走行速度と縞の周期が同期する**: 180 km/h(7200 u/s)と縞の周期 1200 u(RUMBLE_SEGS 3 × 2 × 200 u)により、ちょうど 1 秒ごとに縞が同じ位置に戻る。受け入れ基準 4 の「時間をおいた 2 枚で縞が変わる」は、撮影間隔によっては正しい実装でも成り立たない(評価計画側の撮影間隔 1.0 秒もこれに当たった)。
- **S-15 と §4 の関係があいまい**: §4 は `blur` で押下状態をクリアするとだけ定め、S-15 は `blur` で自動ポーズとする。「`blur` イベントの受信」と「実際のフォーカス喪失」のどちらを条件にするかが書かれておらず、実装が分かれた(xhigh は後者)。
- **近景レイヤーの帯が遠景と重なる**: `bg_near`(下端 y = 180、高さ 56)と `bg_far`(下端 y = 180、高さ 96)の縦位置が重なるため、画像から「近景が速く流れる」ことを確かめるには行ごとの解析が必要になる(評価計画の帯 C の設定もこれで効かなかった)。
- **カウントダウンの数字の大きさ**: 「拡大 6 倍程度」とあるが、全実装とも目視ではそれより小さい数字だった(許容幅が書かれておらず、合否は「大きく」の目視で判定した)。
- **タイトル中の `getState()` の値**: `timeLeft` などを `title` で何にするかが決まっておらず、実装で 0 と 30 に分かれた(合否には影響しない)。
- **ステージ 1 の草の色**: 配色は「橙・桃・青緑(海)」とあるが、草(地面)の色の指定がなく、high は緑にした。
- **評価計画側の問題(参考)**: EVAL §1.3 のボット規則は、速度 0・`|err| ≥ 0.15` から抜け出せない(逸脱 1)。M07 の「`setPlayerX(0.333)` を 1 回だけ」+280 km/h 2 秒は、カーブでの遠心力で交通車に当たるため、seed 42 では 5 実装とも無効になった。
