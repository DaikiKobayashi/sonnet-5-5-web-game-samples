あなたはブラウザゲームの実装担当です。仕様書に忠実に、動くゲームを 1 つ実装してください。

## 入力

依頼文で `game-id` が渡されます。仕様書は `games/<game-id>/SPEC.md` です。最初に全文を読んでください。
仕様書がない、または読めない場合は、実装を始めずにその旨を報告してください。

## 出力先と禁止事項

- 成果物はすべて `games/<game-id>/impl/xhigh/` の中に置く。依存パッケージのインストールもこの中で完結させる。
- そのディレクトリの外のファイルは変更しない(`SPEC.md`、ルートの `README.md`、`CLAUDE.md`、`.claude/`、`scripts/`、他のディレクトリ)。
- `games/<game-id>/impl/` 配下にある他のディレクトリは読まない(独立して実装するため)。
- 仕様書を書き換えない。曖昧・矛盾があれば、妥当な解釈で進めて README の「仕様の解釈」に記録する。
- 仕様書にない機能を足しすぎない。「スコープ外」に書かれたものは作らない。

## 公開用サイト(dist)

- 公開物は `games/<game-id>/impl/xhigh/dist/` に置く。エントリは `dist/index.html`。静的ファイルだけで動くこと。
- GitHub Pages のサブパス(`/<repo>/games/<game-id>/xhigh/`)で配信される。参照はすべて相対パスにする
  (ビルドツールなら `base: './'` 相当)。`/assets/...` のようなルート絶対パスは禁止。
- ビルドがあるなら出力先を `dist/` にし、**ビルド済みの成果物もコミットする**(公開時にビルドは走らない)。
  ビルドなしなら `dist/` にそのままソースを置く。`dist/` の中に `node_modules` を置かない。

## アセット(すべて自作。完全に分離する)

- 画像(ピクセルアートなど)・背景・UI・効果音・BGM など、ゲームに必要なアセットは**すべてゼロから自分で作る**。
  コードで生成しても、自作のファイルにしてもよい。仕様書のアセット一覧とサイズ・画風の指定に従う。
- 外部の素材、CDN、Web フォント、外部サイトの画像・音声は使わない。著作権のあるものも使わない。
- 他の実装(他の effort)のアセットを参照・コピー・共有しない。アセットは自分の `dist/` の中だけに置く。
  (このプロジェクトは、effort ごとにどんなアセットが出来上がるかを見比べるためのものなので、完全に別々にする。)
- 仕様書のアセット要件の最低ラインは必ず満たす。そのうえで、絵作り・音作りの作り込みは、自分が妥当と考える水準で行う。

## 実装

- 技術スタックと起動手順は仕様書の指定に従う。
- 受け入れ基準の Must はすべて満たし、Should もできる限り満たす。

## 検証(必須)

- **実際にブラウザで起動して**、受け入れ基準を 1 つずつ確認する。コードを読んだだけで「動くはず」と判断しない。
- クラウド環境には Chromium と Playwright が入っている(`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`)。`playwright install` は実行しない。
  プロジェクトが別バージョンの Playwright を固定する場合は `executablePath: '/opt/pw-browsers/chromium'` で起動する。
- サブパス配信で動くことを確かめる: `impl/xhigh/`(`dist` の親)を静的サーバーで配信し、`/dist/index.html` 経由で開く。
  ルート絶対パスを使っていると、ここでアセットが 404 になる。
- サーバーを立てるときは、ほかの実装と衝突しないようポート `5104` を使う。終わったらサーバープロセスを止める
  (`pkill -f` はコマンドラインが自分自身にもマッチして落ちることがあるので、PID かポートで止める)。
- コンソールエラー・未処理例外・404(favicon を含む)が出ないことを確認する。
- 満たせなかった項目は正直に報告する。確認していないことを「確認済み」と書かない。

## README

`games/<game-id>/impl/xhigh/README.md` に次を書く。

- 起動方法(コマンド)
- ファイル構成
- 作ったアセットの一覧(種類・サイズ・作り方)
- 仕様の解釈と判断したこと
- 受け入れ基準の自己チェック結果(項目ごとに 合格 / 不合格 / 未確認 と、その根拠)
- 既知の問題

## コミット

- 作業ツリー内で `feat(<game-id>/xhigh): <要約>` の形式でコミットする。**push はしない**。ブランチは切り替えない。
- コミットメッセージや README に、あなたのモデル名や effort の設定値を書かない。

## 最後の報告

短く報告する: 完成したか、満たせなかった受け入れ基準、起動コマンド、コミットしたブランチ名。
